## 方法與隔離

使用先前已驗證的官方 [facebookresearch/sam3 影片介面](https://github.com/facebookresearch/sam3#video-predictor)及相同 `sam3.pt`（SHA-256 `9999e2341ceef5e136daa386eecb55cb414446a00ac2b55eb2dfd2f7c3cf8c9e`），只在每個 session 的首幀送入 `add_prompt(text="smartphone")`，再呼叫 `propagate_in_video`。沒有輸入位置、YOLO 框、GT、未來影格選 ID，亦沒有人工指定哪個候選是 `phone_01`。保留所有官方回傳的非空局部 ID、遮罩、bbox 與 `out_probs`；原始 [SAM3Candidate 記錄](candidates.json)及逐候選 PNG 遮罩位於本資料夾。

兩個 session 沿用既有 test8 的固定取樣視窗：`target_full` f204–f1098 共 150 幀，以及 `same_identity_reinit` f804–f1098 共 50 幀。兩者各自從首幀執行文字偵測，**ID 命名空間彼此獨立**；f804 在既有 V2.6 為 `CONFIRMED_MATCH`，但本實驗並未使用這個身分結果作提示或合併。兩視窗共有 **200 個窗口影格觀測**、**150 個不同來源影格**，重疊的 50 幀在前者的 150 幀中另跑一次。沒有更新 YOLO、SAM 2.1、Re-ID、PersistentEntity、Identity Guard、trusted bank、Memory Graph 或 V2.6 規則；只建立新的 `supplementary_sam3_concept` 子資料夾。

## 延續、遺失與身分邊界

在 f804 session，ID 0 連續出現在 **28 個取樣影格（f804–f966）**；f804、840、852、864、900、924、942 的人工檢查支持它覆蓋同一支原智慧型手機。ID 1 自 f924 連續 6 個取樣影格至 f954，ID 2 自 f924 連續 7 個至 f960；已檢視的 f924、f942 未見兩者互換。這是**局部 ID 的可見時間連續性**，其間每一幀並未做人工真值檢查。

ID 0 在 f966 後不再輸出；f996–f1020 另有新 ID 3。新 ID 是否為原手機、另一手機或錯偵測，本次無可靠物理證據，**不做 re-detect 同一實體的宣稱，也不把任何 ID 寫成 `phone_01`**。沒有觀察到已檢視影格中的明顯 ID switch，這不保證全 200 個窗口觀測都沒有切換。

## 結論與限制

文字概念偵測把 test8 長視窗從 box 的 0/200 變為 109/200 個有遮罩觀測，並在 f924／f942 顯示多候選和短期 ID 延續。這支持「原 box 方案全空**可能與提示模式或其長視窗路徑有關**」的解釋，但沒有隔離官方內部每個機制，也不能由此證明唯一根因。point 原本也可輸出非空遮罩；text 額外帶來候選探索，並增加傳播時間與記憶用量。僅七個影格做物理畫面核對，沒有完整多物件準確率、ID switch 率或對 `phone_01` 的安全身分綁定評估。

**分類為 `CONCEPT_DETECTION_SHOWS_USEFUL_CONTINUITY`，僅限候選探索／局部追蹤。** 這不改變 V2.6.2 `KEEP_SAM21` 的原型決策；依使用者要求，此處停止 SAM 實驗，不展開整合或下一輪調參。

1. 開啟 SAM 3 `smartphone` detection **解決了本次 test8 box 長視窗全空的輸出問題**（text 109/200、box 0/200），但尚未定位 box 失效的唯一原因。
2. 它對 FindMind **有候選探索價值**，能重新產生原智慧型手機候選並在 f924／f942 同時保留三個電話局部 ID，但局部 ID 不等於 `phone_01`。
3. **現在不值得整合進主原型**，因本次沒有完成可信身分合併與安全性驗證，且 V2.6.2 的 SAM 2.1 原型結論維持不變。
